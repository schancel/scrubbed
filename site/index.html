scrubbed

One local pipeline that turns raw scraped web pages into clean training/eval data: encoding repair, main-content extraction, PII scanning, dedup, and language ID — in a single pass per document, with no intermediate files.

Source on GitHub README #!blag

Why scrubbed

Most corpus-cleaning pipelines today are a chain of separate Python tools glued together with intermediate files: ftfy to fix encodings, trafilatura to pull the article out of the page, langdetect to tag the language, Presidio to find PII, a separate dedup pass — each one its own interpreter startup, its own read/write of the whole document, its own copy of the string.

scrubbed replaces that chain with one native binary that does the whole pass per document in a single process: mojibake repair, HTML main-content extraction, PII scanning, language ID, dedup — zero-copy where the data allows it, real OS-thread parallelism across the whole corpus, no intermediate files between stages. Where a case is covered, it's built and verified to match the reference tool's output, not just approximate it — see the numbers below. Coverage is still growing (more encodings, more scripts, more languages), but the bar for anything shipped is drop-in correctness on what it claims to cover.

The pipeline, one command

scrubbed clean-web-document --input page.html --output page.txt
scrubbed clean-web-document --input pages/ --output clean/ --threads 4

Repairs mojibake, extracts the article body out of the page (nav/ads/footers dropped), scans the result for emails/phones/card numbers/IPv4 addresses, and writes a PII-audit sidecar next to the output — one process, one pass, parallel across a whole directory tree.

Verified against the tools it replaces

  • Encoding repair vs. ftfy: on its Latin-1/Windows-1252 scope, scrubbed's mojibake repair matches ftfy exactly against ftfy's own test corpus — all 39 corrupted cases in scope fixed, all 48 clean cases left untouched. More encodings are on the roadmap.
  • Language ID vs. langdetect: 100% classification agreement (11/11) on a real held-out fixture run across scrubbed's 17 supported languages (11 Latin-script plus 6 Brahmic-family: Hindi, Bengali, Tamil, Telugu, Gujarati, Punjabi).
  • Main-content extraction vs. trafilatura: matches trafilatura's held-out gold answers on the pages it processes today; full methodology, current coverage gaps, and the open ticket tracking them are in docs/html-main-content.md.

Also in the pipeline

  • A four-class PII scanner (email/phone/card/IPv4) with report, mask, and opt-in redact modes, publishing a content-free audit record.
  • Exact-byte deduplication across a corpus.
  • A deterministic, model-free language identifier — no embedded model, no network call — reachable from the same generic pipeline as every other stage.
  • An opt-in per-document quality signal: order-0 token entropy plus compression ratio, for flagging degenerate/repetitive text.
  • HTML entity decoding (all 2,231 WHATWG named references), smart-quote and line-ending normalization, and a JSONL streaming mode for corpus pipelines that only need specific text fields touched.
  • Real parallelism across files (OS threads, not green threads), zero-copy input reads, atomic output writes, and an opt-in error journal/manifest for resuming interrupted runs.
  • A bounded WARC/1.1 reader (plain, gzip, and zstd-compressed), a crawl frontier with durable, resumable, duplicate-safe job tracking, bounded HTTP fetch, and link discovery — the building blocks for a full crawl-to-corpus pipeline, with a top-level crawl command still on the roadmap.
  • Declared topical-tag extraction, a source-rights policy engine for permission/takedown decisions across derived artifacts, and structured chunking with stable, content-addressed chunk IDs for downstream corpus formats.

Status

Used today for local, single-machine corpus runs within the scope described above. Proven multi-terabyte-scale operation is still on the roadmap — see TODO.md in the repo for the current, specific list of what's next.

Usage

dub build --build=release
./scrubbed clean-web-document --input page.html --output page.txt
./scrubbed --list-filters
./scrubbed --input path/to/docs --output path/to/clean \
    --filters normalize-line-endings,strip-control
