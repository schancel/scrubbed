# Local HTML metadata route

`scrubbed route-metadata --input PATH --content-output EXISTING_DIR --metadata-output EXISTING_DIR --manifest PATH [--filters CSV] [--retry]` is an opt-in local route. `PATH` is one UTF-8 `.html`/`.htm` file or a directory containing only those files. Directory admission is limited to 65,536 files and 16 MiB total normalized input-relative name bytes; a larger tree is refused before manifest creation or output publication. The two output roots must already exist, be distinct, and be outside the input tree. The manifest is the existing v1 local SQLite format; this verb does not activate the v2 error journal.

The registered `html-metadata` stage produces the `metadata-json:v1` payload from the HTML itself. No sidecar or filename is used as metadata. The content output is the original UTF-8 source after the named filter chain, defaulting to `normalize-line-endings,strip-control`. Each file's basename (or input-relative nested path for a tree) is used under both roots, including the original `.html` suffix in the metadata root. This route creates only needed output subdirectories after preflight.

Both sinks share a typed document identity but publish independently. Both manifest config hashes include a checked, streamed digest of the running executable, so a changed binary cannot verify-skip older payloads. A verified committed sink is skipped on replay. An unresolved destination requires explicit `--retry`; retry does not replace a verified sibling. There is no two-file atomic commit, recovery without inspection, power-loss guarantee, or protection from hostile concurrent path replacement. Symlink, hardlink, path-overlap, and destination-owner checks reject unsafe static routes before publication. A bad UTF-8 input, HTML parse quarantine, or the 64 KiB raw HTML limit leaves both payloads unpublished for that document.

Exit `0` means all admitted files published or verified both sinks, `1` means a document was quarantined or a sink failure was durably recorded, and `2` means invalid arguments, an unsafe route, or a fatal persistence failure. Diagnostics are fixed tokens: `route-invalid-arguments`, `route-incomplete`, or `route-refused`. Inspect the manifest and output roots for per-sink status; the CLI does not print source bytes or private sink keys.
